设备终端与 FRR 命令
========================================

使用位置：浏览器底部“设备终端”。实验应已经部署，目标容器处于运行状态。
双击设备打开终端：FRR 路由器默认进入 ``vtysh``，主机和交换机默认进入 Linux ``sh``。
输入命令前先确认当前是 FRR CLI 还是 Linux Shell，两者使用不同的命令。

.. contents:: 本页操作
   :local:
   :depth: 2

在 FRR 中查看路由和配置协议
----------------------------------------

双击路由器默认进入交互式 ``vtysh``，可连续输入::

  show ip route
  configure terminal
  router ospf
  network 10.0.0.0/8 area 0
  end

路由器还可通过终端工具栏的“Linux Shell”打开独立 shell 标签。

在 Linux Shell 中检查地址与连通性
----------------------------------------

主机和交换机默认进入 ``sh``，可以运行::

  ip -br addr
  ip route
  ping -c 3 10.10.2.10

如果进入的是 FRR 容器的 Linux Shell，可以运行 ``vtysh -c 'show ip route'`` 或
``vtysh -c 'show ip ospf neighbor'``；普通 VPCS/Linux 主机和交换机镜像不保证带有 vtysh。

使用、关闭与重连终端
----------------------------------------

终端实时显示输出，支持 Ctrl+C、
Tab 补全、方向键历史和复制粘贴；补全与历史能力取决于镜像内程序。
使用浏览器常规复制粘贴快捷键；Ctrl+C 用于中断前台程序。
拖动面板或点击“放大”会同步调整容器终端行列数。
容器不需要 SSH 服务或管理 IP，也不需要额外发布容器端口。

切换设备标签、日志标签或收起面板保留连接。关闭终端标签时回收对应会话中
带有会话标识的 shell 与命令进程，设备容器继续运行；后端停止时也会回收会话。
刷新网页后建立新会话，不恢复原 shell 的目录、历史或正在执行的命令。
网络断开后可点击“重连”；设备清理或重新部署会使旧会话失效。
每个页面最多打开 12 个标签，后端最多同时接纳 32 个会话。

FRR 的启动配置如何生效
----------------------------------------

路由器默认使用镜像的 ``/usr/lib/frr/docker-start`` 启动脚本，首次初始化时启用
``bgpd``、``ospfd``、``ospf6d``。Docker 参数开启容器内 IPv4/IPv6 转发。
自定义镜像应兼容这些 FRR 路径；也可在“高级配置”中填写启动命令 JSON 数组。

“FRR 启动配置”用于首次初始化共享目录中的 ``frr.conf``；部署完成网线和地址设置后
校验配置并通过 ``vtysh -b`` 再次应用，保证接口配置恢复。
例如根据实验拓扑填写::

  router ospf
   network 10.0.0.0/8 area 0
  exit

保存刚刚修改的配置
----------------------------------------

在设备仍运行时点击“保存设备配置”，确认逐台成功后再清理设备。普通“保存”按钮保存拓扑，
不会代替 FRR 保存运行配置。完整的保存、清理、重新部署恢复示例见 :ref:`workbench-data-frr`。
