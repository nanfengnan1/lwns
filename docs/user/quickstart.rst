第一次实验：让两台 PC 互通
========================================

本页只使用 Web 工作台。目标是在浏览器中部署两台 PC、两台交换机和一台 FRR 路由器，
从 PC1 ping 通 PC2，再保存配置并清理设备。
所有“点击”和设备命令都在浏览器中操作；还没有工作台地址时，先按 :doc:`workbench-start` 启动。

.. contents:: 实验步骤
   :local:
   :depth: 1

开始前确认
----------------------------------------

* 已取得可用的工作台地址和 Token，后端位于 Linux Docker 宿主机。
* 后端没有使用 ``--preview``；只设计拓扑的模式不能完成本页 ping 验证。
* 已有可用的 FRR 与 Linux/VPCS 镜像；默认示例标签为 ``alpine/frr:latest``、``alpine/vpcs:latest``。

一、连接工作台并确认镜像
----------------------------------------

打开管理员提供的地址：开发部署通常是 ``http://宿主机IP:5173``，普通发布部署是
``http://宿主机IP:8090``，HTTPS 发布入口是 ``https://宿主机IP``。输入对应后端 Token。

登录后应看到左侧设备库、中间画布和右侧属性。点击顶部环境状态，确认主机具备部署条件。
如果提示缺少 Docker、ip、nsenter 或权限，先按 :doc:`troubleshooting` 处理。

打开“镜像管理”，核对所需镜像已加载。缺少时按 :doc:`workbench-images` 导入或引用镜像。
若你的镜像标签与默认示例不同，下一步在每台设备属性中选择实际标签。

二、加载示例并保存
----------------------------------------

点击左下角“双网段路由实验”，画布应出现：

.. code-block:: text

   PC1 -- SW1 -- R1 -- SW2 -- PC2

.. list-table:: 示例地址
   :header-rows: 1
   :widths: 30 35 35

   * - 设备 / 接口
     - 地址
     - 默认网关
   * - R1 eth0
     - 10.10.1.1/24
     - 无
   * - R1 eth1
     - 10.10.2.1/24
     - 无
   * - PC1 eth0
     - 10.10.1.10/24
     - 10.10.1.1
   * - PC2 eth0
     - 10.10.2.10/24
     - 10.10.2.1

点击设备，核对镜像、地址和网关，然后点击顶部“保存”。示例文件是 ``examples/basic-lab.json``。
此时只保存了拓扑，还没有创建容器；需要从空白画布开始时，操作见 :doc:`workbench-editor`。

三、部署设备
----------------------------------------

点击“部署实验”，在底部部署日志中查看进度。等待状态变为“运行中”。
交换机 STP 收敛可能还需要数秒。失败时先查看日志最后的错误，按 :doc:`troubleshooting` 处理后重试。

四、从 PC1 验证连通性
----------------------------------------

双击 PC1，在网页打开的 **PC1 Linux Shell** 输入::

   ping -c 3 10.10.2.10

应收到 PC2 的回复。这一实验使用 R1 的直连路由，不需要先配置 OSPF/BGP。
如果刚部署后的第一次 ping 失败，等待数秒再试；仍失败时在 PC1 用 ``ip -br addr``、``ip route``
检查地址和网关，在 R1 的 FRR 终端用 ``show ip route`` 检查直连路由。

终端的 CLI/Shell 区别见 :doc:`workbench-terminal`。需要观察 ARP/ICMP 报文时，再按
:doc:`workbench-capture` 安装本地启动器并点击连线抓包；抓包不是完成 ping 验证的必需步骤。

五、保存配置并清理设备
----------------------------------------

如果在 FRR 终端中修改过配置，先点击“保存设备配置”，确认逐台成功后再点击“清理设备”。
清理后应回到未部署状态，容器和 veth 被移除，拓扑及已保存的 FRR 配置保留。
需要继续实验时再次“部署实验”，重新检查配置和连通性。

普通“保存”不代替设备配置保存；“删除实验”也不同于“清理设备”。按钮区别和备份方法见
:doc:`workbench-data`。VPCS/Linux 主机 Shell 中的临时修改目前没有通用保存能力。

旧版命令行入口
----------------------------------------

使用 ``frr_init.sh`` 创建 FRR 容器的流程已独立整理到 :doc:`legacy-cli`，不与本页 Web 实验混用。
