实验保存、备份与恢复
========================================

当前已实现拓扑 JSON 保存及 FRR 配置持久化。**完整项目包导入、导出仍在讨论，尚未实现**；
不能把现有“导出 JSON”当作包含全部设备文件和镜像的完整备份。

.. contents:: 本页导航
   :local:
   :depth: 2

每个操作保存什么
----------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - 操作
     - 当前行为
   * - 应用设置
     - 将右侧设备属性应用到当前画布草稿；仍需保存拓扑。
   * - 保存
     - 将设备、连线、位置、地址、启动配置、画布注释及连线优化开关写入后端实验记录；不执行设备的保存配置命令。
   * - 重命名项目
     - 已保存项目立即写入显示名称；未保存项目只修改草稿。不会保存其他待修改内容，也不改变项目 ID、配置目录或部署。
   * - 保存设备配置
     - 对支持的 FRR 设备执行保存，写入共享目录，并将 frr.conf 文本同步到拓扑；逐台返回结果。
   * - 导出 JSON
     - 下载当前拓扑及其中已同步的 FRR 配置文本；不会自动保存设备运行配置，也不包含镜像和其他配置文件。
   * - 清理设备
     - 删除本实验的容器和网线，保留拓扑、共享配置及备份；未写入磁盘的运行配置会丢失。
   * - 删除实验
     - 已保存实验会删除实验记录、设备配置和备份；未保存实验只清空当前草稿。

平时推荐顺序为：编辑拓扑 → 保存 → 部署 → 终端配置 → 保存设备配置 → 检查结果 → 清理设备。
保存部分失败时先处理失败设备，不能仅看到部分成功就清理整个实验。
FRR 的详细操作和恢复示例见 :ref:`workbench-frr-config`。

FRR、主机和交换机的区别
----------------------------------------

* FRR 的 ``frr.conf``、``daemons``、``vtysh.conf`` 位于宿主机共享目录，清理后保留。
  在终端执行 ``write memory`` 也能写入共享文件，但不会自动更新拓扑中的文本；
  导出 JSON 前应在设备仍运行时点击 **保存设备配置**。
* VPCS/Linux 主机及 Linux bridge 模板会根据拓扑恢复端口地址、网关和桥接关系。
  通过 Shell 临时添加的地址、路由、进程或文件尚无通用保存功能。
* 加载 VPP 或其他镜像不会自动增加配置保存能力。手动创建接口也不会自动生成恢复脚本。

宿主机数据与本机数据
----------------------------------------

默认目录位于 Linux 后端的项目根目录：

.. code-block:: text

   .route-ovs-labs/
     <实验ID>.json                 # 拓扑、运行状态、更新时间
     devices/<实验ID>/<设备ID>/
       config-meta.json
       frr/
         frr.conf
         daemons
         vtysh.conf
       backups/<时间-随机标识>/
     images/
       registry.json               # 镜像管理清单，不是镜像文件
       jobs/                       # 镜像任务记录
       uploads/                    # 上传暂存

使用 ``--data-dir`` 时以该参数指定的目录为根；同一数据目录只能由一个后端使用。
设备配置按实验 ID 和设备 ID 定位，修改实验显示名称不会改变这两个 ID。

Docker 镜像仍由 Docker 自己管理，不存放在上述镜像清单中。
Wireshark 抓包文件和启动器连接设置保存在客户端电脑，位置见 :doc:`workbench-capture`。
浏览器保存的面板高度、侧边栏宽度和收起状态属于本机界面偏好，不包含在拓扑 JSON 或数据目录备份中。

导入、导出 JSON
----------------------------------------

点击左下角“导出 JSON”会先应用当前设备属性草稿，再下载版本为 ``1`` 的拓扑文件。
选中注释时也会先应用注释草稿；文件包含注释位置、内容及样式。旧矩形尺寸字段仅兼容保留。
选择“导入 JSON”载入文件后先核对设备、镜像和连线，再保存和部署。
导入文件上限为 1 MiB；当前实验最多 64 台设备、256 条网线，每台设备最多 32 个端口。

**当前导入会保留 JSON 内的实验 ID，不会自动创建一个全新 ID。** 如果该 ID 已存在，
保存时可能更新同 ID 的未部署实验；同 ID 实验仍在部署时会拒绝修改。
若要复制成独立实验，可先在 JSON 中将最外层 ``id`` 改为新的合法值，例如
``lab-ospf-copy``，再导入。只修改 ``name`` 不会创建独立副本。
不要改变设备与连线引用之间的对应关系。

JSON 适合分享拓扑及已同步的 FRR 启动文本，但不包含 ``daemons``、``vtysh.conf``、
历史备份、镜像和任意容器文件。需要完整迁移当前支持的持久化数据时，按以下离线备份步骤操作。

离线备份实验数据
----------------------------------------

以下步骤操作的是 **Linux 宿主机**。备份整个数据目录时，应先处理其中所有已部署实验：

1. 在 Web 保存需要保留的 FRR 配置，确认各设备均成功。
2. 对本次备份目录中的所有已部署实验点击“清理设备”，确认容器已清理、状态回到未部署。
   清理会保留共享配置，避免将旧宿主机容器 ID 和运行状态作为可恢复部署带走。
3. 等待镜像导入、构建和上传结束，停止使用该数据目录的后端。
4. 在项目根目录备份数据。例如默认目录可执行::

     sudo tar -czf "$HOME/route-ovs-data-$(date +%Y%m%d-%H%M%S).tar.gz" .route-ovs-labs

   使用自定义数据目录时，改为对该目录归档。备份文件应放在数据目录外。
5. 记录实际使用的镜像及平台。需要离线搬迁镜像时，对用到的标签执行 ``docker save``，例如::

     sudo docker save -o route-ovs-images.tar alpine/frr:latest alpine/vpcs:latest

   自定义设备镜像也要加入实际清单。仅记住 ``latest`` 标签无法保证重新拉取到相同镜像内容。

此备份包含已持久化的实验数据，不包含容器内存、未保存配置、任意容器可写层和客户端抓包文件。
当前设备配置备份不会自动轮转，长期使用时需关注数据目录占用。

在新目录或另一台宿主机恢复
----------------------------------------

目标宿主机需具备相同的设备模板、兼容的 Docker 平台和对应镜像。
先按 :doc:`workbench` 准备后端及前端资源，保持目标后端停止。
将备份复制到目标机器后，使用一个 **全新空目录** 恢复；以下命令不覆盖已有数据目录::

  sudo mkdir /srv/route-ovs-restored
  sudo tar -xzf /实际路径/route-ovs-data-时间.tar.gz -C /srv/route-ovs-restored
  sudo docker load -i /实际路径/route-ovs-images.tar
  sudo .venv/bin/python script/python/lab_server.py \
    --host 0.0.0.0 --port 8090 \
    --data-dir /srv/route-ovs-restored/.route-ovs-labs

本例对应默认数据目录生成的归档；如果归档内目录名不同，请相应修改 ``--data-dir``。
``mkdir`` 提示目录已存在时，换用新的空目录或先核对其用途，不要直接覆盖。
如果目标已具有完全相同的镜像，可以省略 ``docker load``。

登录新后端，刷新镜像清单，检查实验和 FRR 磁盘配置，再逐个部署并验证连通性。
应重新创建容器和网线，不能使用旧 PID 或旧容器 ID。
后端根目录路径可以变化，但不要在设备运行中搬动仍被绑定挂载的配置目录。

如果只是在同一台宿主机重启后端且保留已部署设备，继续使用原来的数据目录即可，
不需要执行上述清理、归档和恢复流程。
