系统架构
========================================

Web 工作台
----------------------------------------

浏览器负责编辑和展示，Linux 后端负责创建 Docker 设备、veth 网线、设备终端和配置保存。
开发部署使用 Vite 5173 提供页面，并将 API/WebSocket 代理到 Python 后端 8090。
发布部署由后端 8090 同时提供已构建页面和 API，也可增加 Caddy HTTPS 443 入口。
两种部署的详细命令与流程见 :doc:`workbench-start`。

.. code-block:: text

   Windows/Linux 浏览器
      │ HTTP：拓扑、镜像、部署、保存、抓包状态
      │ WebSocket：设备终端
      ▼
   Linux Docker 宿主机：Python 后端（root）
      ├── .lwns-labs：实验和共享配置
      ├── FRR 容器 ── veth ── Linux bridge / 主机容器
      └── tcpdump：按选定端点抓包

   本机 Wireshark ── SSH ── 宿主机转发程序 ── 后端抓包流
      └── 本机 capture.pcapng

Web 中的交换机在容器内使用 Linux bridge，不创建宿主机 OVS。
主机卡片使用 Linux/VPCS 模板，提供 Linux Shell；只有 FRR 模板目前实现运行配置保存。
后端通过容器 PID 操作网络命名空间，不依赖 ``frr_A`` 一类同名 ``ip netns`` 登记。
因此，仅查看 ``ip netns list`` 不能判断 Web 实验是否已经部署成功。

详细操作见 :doc:`workbench`，数据保存和恢复见 :doc:`workbench-data`。

旧版脚本工具的组成与职责
----------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - 组件
     - 职责
   * - FRR 容器
     - 运行路由协议；``frr_init.sh`` 按 ``frr_A`` 到 ``frr_Z`` 命名。
   * - OVS 网桥
     - 为路由器实验提供二层连接，拓扑采集器读取其 Bridge、Port、Interface 信息。
   * - Linux netns / veth
     - 隔离容器网络并连接接口；同名 netns 是容器现有网络命名空间的登记入口。
   * - VPCS 容器
     - 提供测试终端；当前工具通过专用 veth 与目标容器直连。
   * - 管理脚本
     - 创建和清理 FRR 容器、登记 netns、抓包、生成 SVG、管理 VPCS 连接。

旧版脚本连接示意
----------------------------------------

以下仅表示连接关系，实际网桥、接口和地址由具体实验定义::

  Linux 宿主机
  |
  +-- frr_A 网络命名空间 -- veth -- OVS 网桥 -- veth -- frr_B 网络命名空间
  |
  +-- VPCS 网络命名空间  -------- 专用 veth -------- frr_A 网络命名空间

FRR 初始化使用 ``--net=none``，不会自动获得 Docker 默认桥接网络或业务 IP。
当前 VPCS 工具创建直连链路，不经过 OVS，也不自动配置 IP、网关或 DHCP。

旧版脚本状态与生命周期
----------------------------------------

FRR 容器清单保存在调用目录的 ``.frr_containers.tmp``。
VPCS 状态由 ``--state-file`` 指定，旁边的 ``.lock`` 文件用于防止并发修改。
操作同一实验时应使用相同工作目录和状态文件。

容器重建可能改变 PID、容器 ID 和网络命名空间。记录文件不是实验配置备份，
协议配置、地址规划和恢复步骤应另行保存在对应实验目录。

两套管理入口的边界
----------------------------------------

Web 只管理自己创建并标记归属的设备；旧脚本按自己的清单和状态文件操作。
选择一种入口完成同一个实验的创建、修改和清理，避免混用清单。
关闭 Web 后端会结束它的终端和抓包会话，但保留已部署容器；重新使用原数据目录启动可继续核对与清理。
容器被外部重启或连线发生变化时，工作台可能显示“需要检查”，此时先处理异常再重新部署。
