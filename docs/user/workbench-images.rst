镜像管理与设备库
========================================

镜像提供容器的运行环境；把镜像绑定到设备类型后，才能作为设备卡片加入画布。
导入镜像不会自动部署实验，也不会让任意镜像自动获得 FRR 的配置保存能力。

.. container:: doc-meta

   **操作位置**：浏览器顶部 **工具 → 镜像管理**。

   **准备条件**：连接可用的 Linux 后端；Docker 服务可用。

   **完成结果**：镜像已加载并绑定类型，设备库中出现对应卡片。

最常用的三步是：导入或引用镜像 → 设置显示名称与设备类型 → 从设备库添加到画布。
已有实验只缺镜像时，先补齐对应标签，再回到实验点击部署。

设备库显示什么
----------------------------------------

左侧设备库顶部横向排列 **路由器、交换机、PC、防火墙** 四个类别，数字表示各类设备数量。
初次打开只显示分类入口，点击某一类后才显示该类设备；其他类别的设备不会混在列表中。
直接点击上方类别切换，子分类标题前不再设置返回箭头。

设备以紧凑双列排列，圆形图标直径 40px，名称和镜像标签位于下方，可点击添加或拖入画布。
圆形背景采用与画布设备类型对应的配色：路由器蓝、交换机绿、PC 紫、防火墙橙。
每批显示 60 项，点击“显示更多”继续加载；
设备区域独立滚动，顶部分类导航保持可见。子目录不设置搜索框，进入分类后直接浏览设备；
切换类别会重置显示数量并回到列表开头。

镜像管理已移至顶部 **工具 → 镜像管理**，左侧不再放置管理按钮。
新增、改名、修改类型、解绑或删除镜像后，分类数量及设备卡片同步更新；画布中的已有设备保留。

导入或引用镜像
----------------------------------------

点击 **工具 → 镜像管理**，按手头的镜像来源选择：

* **镜像地址**：输入 ``alpine/frr:latest``、``registry.example.com/router:1.0`` 等仓库地址，
  后端执行拉取；也支持指向未压缩 tar 镜像归档的 HTTP(S) 下载 URL。
* **镜像归档**：仅上传 ``docker save`` 生成的未压缩 ``.tar`` 文件，后端直接执行 ``docker load``，
  保留归档中的镜像标签。它不是 ``docker export`` 导出的容器根文件系统。
* **Dockerfile**：选择文件或填写内容，并指定生成的镜像标签。使用 ``COPY`` / ``ADD``
  时可附带 tar、tar.gz、tar.xz 或 zip 构建上下文；所需文件须位于归档根目录。
  上方 Dockerfile 覆盖上下文根目录的同名文件。上下文不接受链接和特殊文件。
* **已有镜像**：填写本机已有的完整镜像名称与标签，将其显式加入清单；不会拉取或删除本地镜像。

Web 镜像导入不自动解压，``.tar.gz``、``.tar.xz`` 等文件请先在本地解压为 ``.tar``。
仅改后缀不能转换格式；后台也会检查上传和 URL 下载的内容是否为未压缩 tar。
成功或失败后自动清理临时上传/下载文件。可直接生成可上传的镜像文件::

  docker save -o frr.tar alpine/frr:latest

若提示 ``does not contain a manifest.json``，请检查文件是否为完整镜像归档，
或是否误选了包含镜像文件的外层 tar。

把镜像加入设备库
----------------------------------------

可填写显示名称，并选择兼容的路由器（FRR）、交换机（Linux bridge）、PC（Linux/VPCS）
或防火墙（Linux）类型，加载后自动加入对应分类；选择“仅管理镜像”则不生成设备卡片。
已有镜像可通过“设置”改名、修改类型或取消绑定，侧边栏同步更新。
一个镜像记录当前绑定一个设备类型；默认清单绑定 FRR 和 PC，交换机需要自行绑定。
如果同一镜像需要作为多种设备使用，可准备不同标签并分别选择类型。
防火墙模板提供 Linux Shell 和默认 4 个端口，镜像需自带防火墙工具，规则由终端配置；
当前不提供防火墙规则表单和规则保存恢复能力。
模板绑定复用现有设备启动、终端和配置能力，不会自动将任意厂商或 VPP 镜像变为受支持设备。

查看任务结果
----------------------------------------

操作以后台任务执行，下方显示日志、成功或失败结果。任务提交后关闭窗口仍继续执行；
上传过程中可以取消。单文件默认上限 8 GiB，可用后端参数 ``--max-image-upload-gib 16``
调整；Dockerfile 上限 512 KiB，上下文解压上限 16 GiB / 100000 项。
若使用反向代理，还需相应调整代理的上传限制。私有仓库使用后端运行账户的 Docker 登录凭据。
镜像操作需要可访问的本机 Linux Docker daemon；设备部署仍需要 root、ip 和 nsenter。

刷新、移出清单与删除镜像
----------------------------------------

“我的镜像”只显示项目默认清单及显式导入、构建、拉取、引用的镜像。
“刷新清单”只更新这些条目的状态，不会自动纳入宿主机其他镜像；命令行加载的镜像需通过
“已有镜像”添加。列表支持名称/标签/ID 搜索、已加载/待加载筛选和设备库可用数量概览。
任务日志可以收起，任务开始自动展开；向上滚动阅读历史日志时暂停自动跟随。

* **移出清单**：移除管理记录及设备库卡片，保留本地 Docker 镜像、容器和已有实验。
* **删除镜像**：仅对本项目任务新建且归属仍一致的标签提供。执行前后端会重新校验，
  并拒绝删除被已保存实验或任何容器使用的镜像；失败保留管理记录。

默认镜像、显式引用的已有镜像和无法确认归属的历史记录会显示“仅引用 · 保留本地”，
只允许移出清单。导入或拉取前已存在的同名标签也受保护。升级会剔除旧版自动发现的未设置条目，
有手工名称或设备类型的旧条目作为引用保留；不会因此删除本地镜像。
类型标题仍保留，显示“暂无设备”；不会再自动生成已删除镜像的设备卡片。
真实模式不展示未加载镜像。设计模式可展示仍在管理清单中的绑定条目，
未加载的条目注明“仅用于设计”；移除记录后同样消失。
设备库变化不移除画布中已有设备。删除标签不保证释放共享镜像层。

管理记录保存在哪里
----------------------------------------

清单文件分为两层：

* ``config/images.defaults.json`` 是源码中的初始默认清单。首次创建管理清单时读取，
  不自动拉取镜像，也不会在重启时重新添加已经删除的管理记录。
* ``<数据目录>/images/registry.json`` 是运行时管理清单，记录镜像地址、名称、模板、
  来源、镜像 ID 和是否存在，导入及删除成功后自动原子写入。使用 ``--data-dir`` 时随之改变。

目录包安装时，运行清单位于所选数据目录的 ``images/registry.json``，默认根目录为
``/var/lib/route-ovs``。只有模板和清单被管理，不会把整个 Docker 镜像库复制到项目目录。
