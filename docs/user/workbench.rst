.. _workbench:

工作台界面与操作入口
========================================

工作台在浏览器中编辑网络拓扑，在 Docker 所在的 Linux 宿主机部署设备。
提供 FRR 路由器、以太网交换机、PC（Linux/VPCS）、Linux 防火墙四种设备类型，所有设备都是容器，
每根网线是一对 veth，两个端点分别位于对应容器的网络命名空间。
“VPCS”卡片在当前工作台中对应 Linux 主机模板，终端使用 sh 和 Linux 命令。

第一次使用先按 :doc:`quickstart` 完成示例。本页用于认识界面、查找操作入口；
详细操作分别放在设备包、镜像、画布、终端、保存与抓包教程中。
已有 ``.rov`` 文件或需要制作 FRR 设备包时，直接阅读 :doc:`workbench-devices`。

支持范围
----------------------------------------

* 添加、拖动、删除设备，选择端口连接和删除网线。
* 紧凑圆形设备、顶部自动对齐、就近连线优化及多行画布注释。
* 新建时填写项目名称；重命名已保存或运行中的项目。
* 左右侧边栏收起、展开和拖动调宽，并记住浏览器中的布局偏好。
* 分类浏览设备库；从 Web 拉取、导入、构建、管理 Docker 镜像。
* Web / CLI 制作 .rov 设备包，导入设备定义与镜像来源，按声明保存和恢复原生配置。
* 配置本机 Docker 镜像、端口数量、IPv4/IPv6 CIDR 地址和默认网关。
* FRR 配置目录读写共享，Web 保存运行配置，清理后重新部署恢复。
* 保存项目，导入和导出版本为 ``1`` 的 JSON 拓扑。
* 顶部菜单集中管理实验与视图；空白启动，通过打开窗口搜索并选择已有实验。
* 部署整个实验、查看日志与实际运行状态、打开交互式设备终端、清理设备。
* 点击已部署 veth 连线，通过本地 Wireshark/sshdump 抓取任一端点流量。

底部“部署日志 / 设备终端”面板上方的分隔条可上下拖动，调整面板高度。
双击分隔条恢复默认高度，聚焦后也可使用上下方向键微调。
高度会保存在当前浏览器中，切换标签、收起再展开或刷新页面后仍会保留；
窗口变小时自动限制高度，为拓扑画布保留空间。

交换机模板在容器内创建 ``br0`` Linux bridge，接入所有已连接端口并启用 STP。
它不创建宿主机 OVS 网桥，也不提供厂商交换机 CLI。第一版不提供虚拟机设备、
跨宿主机连线；运行中的拓扑可以编辑，网络改动通过“应用拓扑”生效。

现有 ``frr_init.sh``、VPCS 管理工具和只读 SVG 拓扑采集器仍独立使用。
工作台不接管这些工具已经创建的容器。

调整侧边栏
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

左右侧边栏支持收起、展开和拖动调宽，具体操作见 :doc:`workbench-editor`。

.. _workbench-start:

部署与启动
----------------------------------------

完整启动流程统一在 :doc:`workbench-start`，先按用途选择开发部署或发布部署，再选择访问协议。
本页下面介绍工作台操作；启动命令、端口、令牌、设计模式与更新方式以该部署教程为准。

.. list-table:: 从这里选择你的部署方式
   :header-rows: 1
   :widths: 25 45 30

   * - 部署方式
     - 启动内容
     - 浏览器地址
   * - :ref:`开发部署 <workbench-deploy-dev>`
     - npm run dev（Vite）+ Python 后端，两个终端
     - ``http://宿主机IP:5173``
   * - :ref:`源码发布部署 <workbench-deploy-source>`
     - 首次 build，日常只运行 Python 后端
     - ``http://宿主机IP:8090``
   * - :ref:`目录包发布部署 <workbench-deploy-package>`
     - 解压安装后由 systemd 启动后端
     - ``http://宿主机IP:8090``

.. _workbench-start-http:

HTTP/1.1：开发与发布的启动入口
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

原来的两条命令仍然可以使用：
``npm --prefix web run dev -- --host 0.0.0.0`` 与
``sudo .venv/bin/python script/python/lab_server.py --port 8090``。
它们属于 **开发部署**，需要两个终端，浏览器访问 **5173**。首次准备和完整操作见
:ref:`workbench-deploy-dev`。

构建前端后只启动后端、浏览器访问 **8090** 的流程属于 **发布部署**，见
:ref:`workbench-deploy-source` 或 :ref:`workbench-deploy-package`。
开发和发布的普通 HTTP 都是 HTTP/1.1；不是从 HTTP/1.0 改成了另一种启动方式。

需要 ``https://宿主机IP`` 入口时，在发布部署基础上按 :ref:`workbench-deploy-https`
配置 Caddy、证书和端口。

设备库与镜像管理
----------------------------------------

按 :doc:`workbench-images` 导入、引用或构建镜像，设置设备类型后从设备库添加到画布。

完成一次实验
----------------------------------------

第一次使用按 :doc:`quickstart` 完成“双网段路由实验”：确认镜像、保存、部署、ping 验证、保存配置，再清理设备。

.. _workbench-edit:

编辑与连线
----------------------------------------

新建与重命名项目、设备接线、地址设置、缩放滚动、自动对齐及注释见 :doc:`workbench-editor`。
部署后也可编辑设备、连线、地址和注释。展示内容使用“保存项目”，设备或网线变更需“应用拓扑”同步到运行环境；
操作区别及重建影响见 :doc:`workbench-editor`。
部署中的设备仍可在终端执行原生 CLI 并保存受支持的配置。

FRR 与设备终端
----------------------------------------

部署后双击设备进入终端。FRR 使用 vtysh，主机和交换机使用 Linux Shell。命令示例和连接管理见 :doc:`workbench-terminal`。

连线抓包与本地 Wireshark
----------------------------------------

点击已部署网线 → “在 Wireshark 中抓包” → 选择端点/BPF → “准备抓包” → “打开本机 Wireshark”。
密码认证无需私钥；未启用自动开始时，在 Wireshark 的 SSH 接口配置中输入密码并开始。

新版默认将 ``capture.pcapng`` 保存到浏览器所在电脑的 ``~/route-ovs/captures`` 独立子目录，
Windows 对应 ``%USERPROFILE%\route-ovs\captures``。Web 会话显示完整目标路径，可复制到本机使用。
安装步骤、认证配置、状态含义和排障见 :doc:`workbench-capture`。

.. _workbench-frr-config:

FRR 配置保存与恢复
----------------------------------------

“保存设备配置”与拓扑“保存”不同。FRR 的操作步骤已集中到 :ref:`workbench-data-frr`；
JSON 导入导出、宿主机备份与恢复也在 :doc:`workbench-data` 中说明。

保存、回滚和状态核对
----------------------------------------

源码默认数据目录为项目根目录的 ``.route-ovs-labs/``，目录包默认为 ``/var/lib/route-ovs``，
可通过启动参数或系统配置修改。每个实验文件分别记录拓扑和运行时归属。
同一个数据目录只能启动一个后端。运行数据、锁和 Python 缓存不应提交到 Git。

容器名为 ``rov-实验ID-设备ID``。创建前不接管同名旧容器；每次部署使用独立的
归属标签。失败时尝试只回滚本次实验的容器，删除容器网络命名空间时同时移除 veth。
若 Docker 不可用或归属发生变化，保留状态并报告清理未完成，便于恢复后重试。

关闭后端不会自动删除已部署设备。重新启动同一数据目录，可查看和清理它们。
后端中断留下的部署记录会提示清理后重试。
如果设备在外部重启、端口被关闭或网线丢失，状态会显示“需要检查”，
不会仅凭保存过的拓扑宣称链路运行正常。

使用后检查
----------------------------------------

完成实验后可以按下面几项确认结果：

1. 重新打开已保存项目，检查设备、位置和连线是否一致。
2. 部署后在终端检查地址、路由和连通性；状态异常时先查看底部部署日志。
3. FRR 保存后查看右侧“查看磁盘配置”，清理重建后核对配置恢复。
4. 抓包结束后在本机用 Wireshark 打开保存文件，确认能读取预期报文。
5. 清理设备后确认实验回到未部署状态；需要长期留存时按 :doc:`workbench-data` 备份。

常见问题见 :doc:`troubleshooting`；开发模式、自动化测试和真实 Docker 集成测试见
:doc:`../developer/workbench`。不需要为日常使用运行测试脚本。

尚未实现的功能
----------------------------------------

完整项目包保存/导入导出、VPP 手动端口发现与在线接线仍属于待办或讨论方案。
现有“保存”和“导出 JSON”继续按当前拓扑机制工作；载入新 Docker 镜像不代表已经适配其 CLI、
接口管理或配置恢复能力。当前不提供多用户权限体系、虚拟机设备和跨宿主机连线。
